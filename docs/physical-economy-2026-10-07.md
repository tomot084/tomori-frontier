# 木材の流れを中心にした改善

開始main: `407884e`。作業ツリーはclean、origin/mainと一致。既存のBabylon.js、
GameModel、v1セーブ、市場、crew、投資、建築、戦闘、工房を土台として改修。
別ゲーム・別通貨・別投資台帳は作らない。

## 実装前の視覚比較

390×844で現在版を起動し、`production-before-390.png`を撮影・実画像閲覧。
今回の6枚（10月7日分）をすべて個別に実画像として開き、連続体験として確認。
参考の人物・肉・雪・UI・ロゴ・配色は使わない。

| 観点 | 現状 | 参考から読み取った改善方向 |
| --- | --- | --- |
| 人物・占有率 | 頭と脚が細く、服・工具と混ざる | 大きな頭、胴・腕・脚の分離、向きの読める姿 |

`same-camera-kaykit.png` で確認。人物の比較とカメラ拡大を分けて評価した。
KayKitの頭・胴・手足の分離が明確なため採用。

## 統合したループ

- 木を打つ → 木が反応・倒れる → 丸太drop → 吸い寄せ → 背中のスタック。
- 製材所右のINPUT（465,430）に近づくと1本ずつ投入。通常95ms、40本超は65ms。
- 近くにいる主人公、製材担当、またはコンベアが工程を動かす。誰もいなければ停止。
- INPUT → 搬送する丸太 → 回転刃・切削反応 → 板材 → 左のOUTPUT（295,430）。
- OUTPUTへ近づくと1枚ずつ背負う。板材は丸太とは別の板形状。
- 市場（610,500）へ運び、1枚ずつ客へ渡す。灯貨は客から金庫へ飛び、蓄積。
- 金庫（650,560）へ近づくと灯貨が吸い込まれる。所持数は吸い込み時間後に増える。
- 板材も建築へ使える。旧木材での直接建築も維持し、旧進行を強制変換しない。

初売上までは製材→OUTPUT→市場→金庫へ案内。建築・探索は維持。
最初は自分で製材所の近くに立って作業し、板材を運んで販売する。

## 投資とNPC

既存investmentTiles / InvestmentSystem / LanternCrewへ統合し、計14投資。
既存の道具・容量・売値・製材速度・OUTPUT/市場容量・仲間の速度・回収・討伐に加え、
製材担当10灯貨、運搬係12灯貨、コンベア24灯貨を地面タイルで購入できる。
木こり8/16灯貨、販売係6灯貨、容量5灯貨（1段階+20、最大120）、道具7灯貨などと競合する。
「製材所＝木の採集量アップ」は実製材速度アップへ変更。

木こりは既存の建築/市場ルート選択を維持。市場ルートでは生の丸太を製材所INPUTへ
運ぶ。歩行、斧作業、hit、伐採、1個ずつpickup、背負う、運搬、荷下ろしを表示。
運搬係はOUTPUTから市場へ実際に歩き、板材を持ち、1枚ずつ降ろす。
製材担当は加工場で作業し、自分が離れても製材を継続。
販売係は市場から客へ歩き、板材を1枚ずつ販売する。
コンベア購入で実際の青緑/灯色の設備と動くベルトが出現し、速度2倍・連続加工。

主人公は青緑、木こりは黄土/緑、運搬係は青、製材担当は橙、販売係は灯色、
客は紫/淡緑。KayKitの同じ基本モデルで服・帽子・斧・荷物を使い分ける。
歩行/待機/斧/拾う/被弾クリップと手への道具接続を使い、向きは補間する。

## セーブ・性能

`tomori-frontier-v1` / version 1、既存資源・建築・強化・HP・位置を維持。
既存economyにproductionを追加（input/output/carried/processing/clock、conveyor、
hauler、sawyer、uncollected、collecting/collectionClock）。欠ける値は安全なdefault。
旧stockも維持して売れる在庫として引き継ぐ。既存sawmillレベルは製材速度へ引き継ぐ。

運搬中の板材は保存OUTPUT内に予約として残し、描画とプレイヤーpickupから除外。
到着して1枚降ろした時だけOUTPUTを減らす。reloadは予約を解除して元在庫を復元し、
重複・消失を防ぐ。回収飛行中の灯貨もcollectingとして保持する。
販売係は客への実距離を確認し、前回の市場への距離を到着判定に使わない。
到着前に予約商品から売上を発生させない単体テストも追加した。

背負う丸太は共有geometry/materialの最大100インスタンス、板材と4在庫はthin instances。
内部数量とは別に100個まで表示し、画面上端で自然にクリップ。カメラは荷物の高さに
合わせてズームアウトしない。2本/段、位置・段角度・移動時の位相ずれで量感を表す。
4在庫は固定行列バッファ、移動物は木/板/灯貨各24の再利用プール。
伐採dropも種類ごとの共有形状と再利用プールへ変更し、繰り返し採集でgeometryを作り直さない。
低FPS時に240msで切り捨てていた経過時間を最大1秒まで受け取り、60ms以下のサブステップで進める。
非表示・pause時は従来どおり進めず、復帰時に基準時刻をリセットする。
軽量表示時はPCも内部画面の長辺を720px以内へ抑える。
主人公の旅靴・NPCの運搬車の速度に歩行クリップのテンポも合わせる。
大量スタックへ影は付けず、既存DPR制限・低速時品質fallback・カメラ外cullingを維持し、在庫とNPCは500座標単位外で描画・ポーズ更新を止める（経済は進む）。
素材は451KBの単一GLB、全NPCは同じasset containerとgeometry/textureを共有。

## 三回の視覚自己レビューと修正

1. **人物・木・カメラ・積載**：空荷と70本の実画面を閲覧。主人公が大きく人として読め、
   丸太が画面上端まで達する差を確認。INPUTの前を木が覆う、案内が脚と重なる問題を修正。
   木は幹を太く長く、樹冠を狭め、工程周辺を空けた。半視野7.8→7.3。
2. **加工・在庫・販売・灯貨**：INPUT75/OUTPUT60のfixtureで実画面を閲覧。
   thin instance登録不足で在庫が表示されない重大問題を発見・修正し、再撮影して山を確認。
   板材を丸太と別形状で背負い、回収後のHUD反映に変更。検査用の行列一覧が空在庫をキャッシュするため、実GPUバッファで検査するよう修正。
   ベルト方向をINPUT→刃へ揃え、ベルト上の加工中丸太も実物で表示。再レビューは稼働余地を残した
   INPUT75/OUTPUT45でも撮影し、処理と完成品の両方を確認。
3. **NPC・自動化**：自分だけの開始状態と、木こり2/運搬/製材/販売/ベルト所有状態を撮影・閲覧。
   人物の服・帽子の違いを強め、荷物・道具を役割別に表示。募集パッドの巨大な置物を
   削り、生産ラインを読みやすくした。運搬予約の競合は保存・容量・実販売テストで修正。

比較画像・fixture・原本・参考画像はローカルのignored領域のみ。実プレイE2Eでは資源を
付与せず、移動フックだけで実採集→製材→販売→購入→NPCの生産を通す。
