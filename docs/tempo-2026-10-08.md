## 数量と描画の分離

`cargo.ts` の `visualStack()` は10 / 100 / 500 / 1000 / 5000 / 10000個を10 / 24 / 42 / 56 / 80 / 100個の表示へ変換する。木材・石材・板材はそれぞれ最大100個。木材は背中に2本ずつ積み、高い荷物は画面上端を超える。さらに束の幅は1000個で1.3倍、5000個で1.75倍、10000個で2.3倍まで伸び、上端が見えなくても大量積載が分かる。木材・石材は共有形状のinstance、板材はthin instance。所持数の変更によって新しい積載meshを作らない。

資源ドロップは1表示に `amount` を持ち、1回の収穫は最大16表示、同時に最大128表示。表示枠が埋まっても同じ資源に数量をまとめ、報酬を切り捨てない。満杯に近い所持枠では入る数量だけ取得し、残りのドロップ数量を保つ。散る→浮く→加速して吸収する。回収表示とHUD更新はまとめる。

敵は3種の共有形状を使い、96体の固定actorを再出現時に再利用する。画面外は表示を省略。破片・命中・波紋・投入は最大48個の同時演出、非表示の再利用プールは最大128個。製材・市場の飛行は既存の各24個の固定プールを維持する。

製材INPUTでは少量は従来どおり1本ずつ、大量は残量に比例したまとめ投入で減らす。数量は厳密に保存し、飛行表示は固定数に抑える。OUTPUT・販売・雇用・投資・建築のルートと建設費は継続する。

## リセット

設定内に「セーブデータをリセットしますか？」とキャンセル／実行を表示する。標準 `window.confirm()` に依存しない。キャンセルはモデルとLocalStorageを変更しない。実行は移動入力を解放し、旧ページの保存を止め、`tomori-frontier-v1` を削除して再読み込みする。blur / visibilitychange による旧状態の再保存を防ぐ。新しいGameModel・UI・3D worldを初期化し、新規開始画面へ戻す。

旧v1セーブキー・進行・建築途中・投資・生産在庫・仲間を維持する。旧容量Lv.4 / 5も読め、10000容量として扱う。容量強化の新規購入はLv.3まで。

## 検証方法

`tests/tempo.test.ts`：群れの殲滅・移動継続・再出現、表示飽和時の報酬保全と部分回収、強化採集、10000所持保存、6段階の表示、大量INPUT投入の数量保存。

`tests/browser/tempo.spec.ts`：3サイズで実touch相当の移動と停止、実採集100以上、橋の建築、周辺10体以上の敵と連続撃破、灯貨回収、工房での容量・採集強化、実採集1000以上、保存復元を操作。6段階の巨大積載の境界は互換セーブの所持数量を用いた専用fixtureでも確認する。10000個をINPUTへ荷下ろしし、生産数量の保全を確認。タッチのリセット取消・実行、キー削除、初期状態、新規採集を確認する。

実Android / iOS端末の性能は未測定。ブラウザ操作はChromiumのタッチエミュレーション、描画はSwiftShader。FPSを実機性能と同一視しない。
