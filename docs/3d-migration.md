# 3D表示への移行判断

## 現状分析と再利用

旧版の `src/main.ts` はPhaser Scene内に描画・入力・採集・戦闘・UIが混在していた。`src/data.ts` はエンジン非依存で、資源、採集物、敵3種、強化5種、建築3段階、コスト、Save、投入・強化・復元をそのまま利用できた。

この移行では **data.tsを変更せず**、Scene内の実行ロジックを `simulation.ts` のGameModelへ移した。数値、採集対象53個・敵14体の配置、採集範囲、追跡範囲、攻撃間隔、素材上限、建築投入のテンポ、復活時間、工房の安全・回復を引き継いだ。食料回復と自動保存のタイマーだけは独立させ、回復中でも定期保存を止めない。

セーブは引き続き `tomori-frontier-v1` / version 1。x/yは旧版の座標単位を保持し、3D表示だけ40単位を1m相当に変換する。資源・コイン・強化・開放・建築途中・HP・位置・プレイ時間・クリア状態の読み込みに変換処理は不要。

## 比較と採用理由

| 項目       | Phaserを維持した2.5D                                | Babylon.jsの3D                                                        |
| ---------- | --------------------------------------------------- | --------------------------------------------------------------------- |
| 立体感     | 描き込んだスプライト／事前レンダリングが必要        | 立体モデルの陰影と奥行きを直接表現                                    |
| 背負う荷物 | 向き・所持量別の画像と描画順を調整                  | 背中の階層へ丸太・石を配置                                            |
| 道具と採集 | 向き別のモーション素材が必要                        | 両腕と道具のTransformで振りかぶり→打撃                                |
| 影・建築   | 自作の擬似影と前後関係を保守                        | 接触影＋方向光の影、立体の基礎・梁・門・灯台                          |
| 実装コスト | Sceneは残せるが、画像制作・向き別表現の負担が大きい | 初回にロジック分離とモデル制作が必要。その後は同じモデルを再利用      |
| スマホ     | 2D描画の負荷は抑えやすい                            | GPU負荷の管理が必要。低ポリ・共有素材・カリング・低解像度の影で抑える |
| Pages      | 静的配信可能                                        | 同じく静的配信可能。CDNやサーバーは不要                               |

今回の主要要件は立体モデル、実際の積み荷、道具の大きな動作、地形と自然な陰影なのでBabylon.jsを採用した。Phaser Graphicsを改善する方針は採用していない。

## 表示層

- `models.ts`: オリジナル低ポリモデル。枝、樹冠、鉱脈、ベリー、灯守の顔・衣服・装備、関節と積み荷。頂点カラーと共有素材で結合。
- `scenery.ts`: 草地・岸辺・層になった崖、踏み跡・花・草、工房、実際に板や柱が組み上がる建築。
- `view3d.ts`: 正投影の斜めカメラ、追従、陰影、対象の白フラッシュ・揺れ・破壊、物理的なドロップと吸着、運搬、数字。
- `input.ts`: native pointer captureの仮想スティックとキーボード。カメラの向きに合わせて共通移動ベクトルへ変換。
- `ui.ts`: 大きい資源カード、目標、HP、施設でのみ開く工房パネル。

参考ゲームの画像、キャラクター、ロゴ、UI部品は使っていない。外部の画像・モデル・フォント・音・生成サービスは使わず、自作の3DモデルとSVGアイコンで構成する。

## スマホ向け制限

- DPRは1.25相当まで。負荷が高い場合は解像度と影の更新頻度を下げる。設定からも軽量表示へ変更可能。
- 正投影、方向光1本＋環境光、512pxの影。重いPBR、反射、水面シェーダー、後処理ブルームは使わない。
- 反復する草花・地形は頂点カラーでメッシュを結合。静的メッシュの行列を固定する。
- 採集物と敵はカメラ付近のみ表示。ロックされたエリアの採集物・敵は表示しない。
- 積み荷は丸太8本・石4個・実の袋1個まで。ドロップ64個、3D破片48個、浮き数字32個まで。
- 開発・E2EのinspectからFPS、描画三角形数、メッシュ数、内部解像度、積み荷数を確認できる。端末で60fpsを保証するものではない。

公式資料: [カメラ](https://doc.babylonjs.com/features/featuresDeepDive/cameras/camera_introduction/)、[影](https://doc.babylonjs.com/features/featuresDeepDive/lights/shadows/)、[最適化](https://doc.babylonjs.com/features/featuresDeepDive/scene/optimize_your_scene/)。
