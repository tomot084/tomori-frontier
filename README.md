# 灯芽の開拓者 / Tomori Frontier

**[ブラウザで遊ぶ](https://tomot084.github.io/tomori-frontier/)**

霧に眠る浮島を、小さな灯守が復旧するオリジナルの3D Idle Arcade。
CC0の人物・樹木素材をTomoriの見た目に合わせ、独自の資源スタック、精霊、建物、地形、エフェクトと組み合わせています。素材の出典は [docs/asset-sources.md](docs/asset-sources.md) に記録しています。

スマホはフィールドをドラッグ、PCはWASD / 矢印キーで移動。採集・攻撃・回収・建設への投入は自動です。敵の灯貨を工房で使い、攻撃・採集・移動・HP・容量を育てます。通常移動は従来の40%増、戦闘島には8体ずつの群れが登場し、周囲の敵をまとめて攻撃します。木材・石材容量は500→2000→5000→10000へ伸びます。工房は回復・安全地帯です。HPが低いと実を使って回復し、倒れても素材を保って野営地へ戻ります。

木を切って丸太を拾い、背中へ高く積んで製材所の右のINPUTへ。少量は95ms間隔で1本ずつ、大量は束で素早く降ろし、丸太が加工機へ流れ、左のOUTPUTに板材が積み上がります。最初は自分が製材所のそばで作業し、OUTPUTから板材を背負って市場へ運びます。1枚ずつ客へ渡すと灯貨が金庫に積まれ、近づいて回収できます。丸太も板材も建築に使えます。

投資候補は28種類。道具・容量を育てるか、木こり・製材担当・運搬係・販売係を雇うか、コンベア・製材速度・在庫容量・売値へ投資するかを選べます。コンベアを買うと設備と動くベルトが出現し、離れていても製材が進みます。木こりは木へ歩き、切り、拾い、積み、1本ずつ降ろします。既存の建築／市場ルートを維持し、市場ルートの原木は製材所INPUTへ、板材は運搬係が市場へ運びます。投資パネルは補助一覧で、地面の募集・設備予定地へ近づいて購入し、購入後は閉じて世界の変化を見られます。

三つの開拓を約5〜10分で遊ぶ規模です。クリア後も採集・戦闘・強化を続けられます。資源・敵は再生するため、素材不足で詰みません。荷物が満杯なら建設地点へ運ぶか背かごを強化してください。

テンポ改善の数値・描画上限・リセット修正・確認手順は [docs/tempo-2026-10-08.md](docs/tempo-2026-10-08.md) に記録しています。

## 追加の仕事と霜灯群島

木こり小屋80、採掘班の詰所95、灯実果樹園55、レンガ窯160、板材分岐所70、霧止め装置120灯貨を追加。木こりと採掘班が実際の資源へ歩き、果樹園では庭師が育った実を摘む。窯は木1・石2からレンガを焼き、出荷係が市場へ運ぶと1個8灯貨が金庫に積まれる。分岐の運搬係は板材を建築か市場へ振り分ける。霧止め装置の光の輪では敵が減速する。

探索中に見つかる宝箱は一度だけ開き、開封済みの見た目と記録が残る。守護獣の祠75灯貨を修復すると、大型の守護獣と戦える。地面に現れる攻撃予兆を避け、撃破すると実際の戦利品120灯貨が散る。

第3島の航路150灯貨を復旧すると、別ステージ「霜灯群島」へ渡れる。霜根の森・晶石渓谷・熔灯高原の3エリア、霜牙・晶甲、違う資源配置・建築費用・設備配置を持つ。帰りの航路は最初から開いている。資源と装備は共有し、建築・設備・在庫・探索・討伐は群島ごとに保存する。

今後、似た形式の別ステージを追加するための定義と共通コンテンツを分けた。手順と保存・描画の約束は [ステージとコンテンツの追加方法](docs/stage-and-content-authoring.md) を参照。

## 島を変える設備投資

実装と検証・比較画像の記録は [世界に建つ投資](docs/world-investments-2026-10-09.md) にまとめています。

第2島には未完成の砲台土台と採掘機の基礎、第3島には回収塔のソケットがあります。予定地へ近づいて既存の投資画面から建設します。購入時は設備が立ち上がり、作業を始めます。

| 投資 | 灯貨 | 解放 | 世界で起こること |
| --- | ---: | --- | --- |
| 自動砲台 | 150 | 第2島 | 旋回→実弾→衝突→撃破→通常の戦利品。基本敵は3発、0.65秒間隔。射程180。 |
| 照準アンテナ | 90 | 砲台建設後 | アンテナが増え、射程250で隣の群れも狙う。 |
| 双砲身 | 180 | 砲台建設後 | 2本の砲身が別々の敵を向き、同時射撃する。 |
| 自動採掘機 | 120 | 第2島 | ピストンとドリルで実際の岩を掘る。石材を最大500保管し、近づくと受け取れる。 |
| 資源回収塔 | 140 | 第3島 | 光の輪（半径240）内のドロップを吸引。各素材2000まで保管し、近づくと受け取れる。 |
| 高速コンベア | 100 | 第2島・ベルト購入後 | 追加の金色モーターと速いベルト。通常コンベアの2倍の搬送・製材。 |

コンベアはINPUTからOUTPUTまで続く幅広のレールと動く矢印を持ち、稼働時だけ灯りが点きます。未購入の製材所は、主人公または購入済みの製材担当が近くで作業する条件を維持しています。採掘機は岩の再出現を待ち、在庫が満杯なら止まります。回収塔も満杯の素材は吸引しません。砲台は第2島の限られた範囲を援護するため、探索先全体の戦闘は主人公の仕事として残ります。

灯貨300なら砲台＋採掘機で270、高速コンベア＋採掘機で220、砲台＋照準アンテナで240。雇用・装備・販売設備にも使えるため、固定の購入順はありません。

## 3D移行と既存セーブ

旧Phaser版の進行を引き継ぎ、表示をBabylon.jsへ移行しました。`tomori-frontier-v1` のKEYと座標単位を維持し、旧版の資源・建築途中・開放・強化・位置・HPを続けられます。市場と雇用の状態は追加のeconomy項目に保存します。追加項目のない旧セーブでは加入済みの仲間を引き継ぎ、新規ゲームでは任意に雇います。加工・在庫・運搬予約・回収途中の灯貨も保存します。旧進行の分析は [docs/3d-migration.md](docs/3d-migration.md)、生産ラインの視覚比較は [docs/physical-economy-2026-10-07.md](docs/physical-economy-2026-10-07.md)、通常画面の整理は [docs/progressive-disclosure-2026-10-07.md](docs/progressive-disclosure-2026-10-07.md) に記録しています。

## 開発

Node.js 24 / TypeScript / Babylon.js 9 / Vite。バックエンド・外部サービス・CDN素材・有料素材はありません。すべてGitHub Pagesから静的配信します。

```sh
npm ci
npm run dev
npm test
npx playwright install --with-deps chromium
npm run test:browser
npm run build
# ビルド済みの静的ファイルでもブラウザ検証
npm run test:production
```

Playwrightは390×844 / 412×915（touch有効）/ 1280×720、縦横切替、DPR3を確認します。既存の通し進行ではE2Eフックで位置だけを移動し、本体の採集・投入・戦闘・強化で橋→門→灯台を通します。既存の通し進行では資源や進捗を付与しません。新設備の比較テストは第2・第3島の保存フィクスチャから始め、実際の購入ボタン・戦闘・採掘・回収を検証します。実採集→INPUT→製材→OUTPUT→市場→金庫→雇用→コンベア→再投資と、旧版の保存互換も別ケースで検証します。

`npm test` はエンジン非依存の資源・建築・強化・移動・戦闘・復帰・セーブを検証します。

開発中、またはURLに `?e2e` を付けたときだけ `window.__game` が利用でき、state / position / entities / input / save / inspectで確認できます。inspectは描画エンジン・FPS・三角形数・メッシュ数・積み荷・内部解像度も返します。通常プレイでは公開しません。

```sh
# 共通移動入力を実際に操作する追加の連続プレイレビュー
node scripts/playthrough.mjs
```

## 構成

- `data.ts`: 設定・互換Save・純粋な進行処理。
- `investments.ts`, `investment-view.ts`, `crew.ts`: 投資先、木材市場、配達・採集運搬の仲間と地面タイル。
- `simulation.ts`: エンジンから独立したPlayer / Gatherable / Enemy / DropItemと採集・戦闘・建築。
- `models.ts`, `scenery.ts`: オリジナルの低ポリモデル、関節、地形、環境、小物と建築。
- `stages.ts`, `content.ts`: ステージの配置・色・敵構成・解放順と共通コンテンツのカタログ。
- `settlements.ts`, `settlement-view.ts`: 新しい採集班・果樹園・加工・分岐・防衛・守護獣・宝箱。
- `world-machines.ts`, `machine-view.ts`: 砲台の実弾衝突、採掘、吸引・保管、設備の建設と可動部。
- `production-view.ts`: 丸太/板材/灯貨の在庫・飛行プールと動く生産設備。
- `view3d.ts`: カメラ、陰影、描画範囲、モーション、破壊・取得・投入の演出。
- `input.ts`, `ui.ts`: pointer capture、画面方向へ移動する共通入力、コンパクトなHUD、近接アクション、工房UI。
- `.github/workflows/pages.yml`: main pushでtest / browser test / build / Pages deploy。

DPRは1.25相当まで。影は512px。低ポリの共有素材と静的メッシュ結合を使い、カメラ外を非表示にします。所持数と積載表示を分離し、木材・石材・板材は10000所持でも各最大100個の共有形状で積載。量が増えるほど背中の荷物が高く伸びます。INPUT/OUTPUT/市場/金庫はthin instanceで各100個まで表示。木材/板材/灯貨/石材/実の移動物は各24個までの再利用プール。必要になった分だけ生成する。砲台の実弾は24発の固定プールで、移動区間を使った衝突判定。設備は静的部分を結合し、550以内だけ描画。設備の影対象は追加せず、石材と保管箱も各24個のinstanceを再利用。袋1個、数量をまとめたドロップ128個、3D破片48個、浮き数字32個まで。敵は各戦闘島48体、共有形状のinstanceと固定actorで再出現し、追跡・更新距離を制限します。演出meshも再利用します。低速時は内部解像度と影の更新頻度を下げ、設定からも軽量表示を選べます。WebGL対応ブラウザが必要です。

LocalStorageへ3秒間隔、建築・強化・フォーカス喪失時に保存。端末・ブラウザごとに独立します。設定内のリセット確認はキャンセル／実行を選べ、削除後の旧状態の再保存を防いで新規開始へ戻ります。実機のSafari / Androidによる検証は未実施で、自動検証はChromiumのタッチエミュレーションです。
